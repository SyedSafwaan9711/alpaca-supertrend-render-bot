# Alpaca Supertrend Crypto Bot

Headless crypto trading bot based on Alpaca's original `supertrend_crypto_bot`
example. This version runs as a Render web service, uses environment variables
for all secrets, exposes health/status/control endpoints, and defaults to safe
paper-trading observation.

This is rule-based software, not an LLM trading brain. Paper trading results do
not predict live trading results, and this project does not promise profit.

## Operating Modes

`BOT_MODE=ASSIST` is the default. The bot stays alive, authenticates with Alpaca,
fetches market data, evaluates the supertrend signal, and reports status. It will
not open autonomous trades. Protected manual endpoints can be used for buy, sell,
and close-position actions.

`BOT_MODE=AUTO` lets the loop place strategy-driven orders when risk checks pass.
AUTO can be paused immediately with `/pause-auto` and stopped with
`/emergency-stop`.

## Trading Modes

`TRADING_MODE=paper` is the default and must use
`https://paper-api.alpaca.markets`.

`TRADING_MODE=live` is intentionally gated. It must use the live Alpaca endpoint
and `ALLOW_LIVE_TRADING=true`; switching to live should be done only after a
separate review of keys, sizing, and risk limits.

## Required Environment Variables

See `.env.example` for a complete template.

Required secrets:

- `ALPACA_API_KEY`
- `ALPACA_SECRET_KEY`
- `ADMIN_TOKEN`

Important runtime settings:

- `ALPACA_BASE_URL`
- `TRADING_MODE`
- `BOT_MODE`
- `SYMBOLS`
- `TIMEFRAME`
- `POSITION_SIZE_PCT`
- `MAX_DAILY_LOSS_PCT`
- `COOLDOWN_MINUTES`
- `MAX_OPEN_POSITIONS`
- `ORDER_INTERVAL_SECONDS`
- `LOG_LEVEL`
- `DRY_RUN`
- `HOST`
- `PORT`

`DRY_RUN=true` is the safest default. With dry-run enabled, the bot still
authenticates, fetches data, evaluates signals, and records risk decisions, but it
does not submit orders.

## Local Run

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
# edit .env with paper Alpaca keys and a long random ADMIN_TOKEN
.\.venv\Scripts\python.exe app.py
```

Run tests:

```powershell
.\.venv\Scripts\python.exe -m pytest tests -q
```

## Render Deployment

This repository includes `render.yaml` for a single free-tier web service.

Default Render settings:

- `BOT_MODE=ASSIST`
- `TRADING_MODE=paper`
- `DRY_RUN=true`
- `SYMBOLS=BTC/USD`
- `TIMEFRAME=1Min`

Secrets are not committed. Set `ALPACA_API_KEY` and `ALPACA_SECRET_KEY` in the
Render dashboard. `ADMIN_TOKEN` is generated by Render when using the Blueprint.

## Oracle Always Free Deployment

Use `deploy/oracle/install_ubuntu.sh` on an Ubuntu Oracle VM, or
`deploy/oracle/install_oracle_linux.sh` on an Oracle Linux VM. The installer
adds Python dependencies, pulls this repo, creates a virtualenv, and registers a
`systemd` service with `Restart=always` so the bot comes back after crashes or
VM reboots.

Runtime secrets belong in `/etc/alpaca-supertrend-bot.env` on the VM, not in Git.
For a private VM-only health endpoint, set `HOST=127.0.0.1` and leave Oracle
ingress closed for port `8000`; check status over SSH with:

```bash
curl http://127.0.0.1:8000/health
sudo systemctl status alpaca-supertrend-bot --no-pager
sudo journalctl -u alpaca-supertrend-bot -f
```

For paper autonomous testing, use `TRADING_MODE=paper`, the paper endpoint,
`BOT_MODE=AUTO`, and `DRY_RUN=false`. Keep `ALLOW_LIVE_TRADING=false`.

## Endpoints

Public:

- `GET /health`
- `GET /status`

Protected with `X-Admin-Token: <ADMIN_TOKEN>` or
`Authorization: Bearer <ADMIN_TOKEN>`:

- `POST /pause-auto`
- `POST /resume-auto`
- `POST /set-bot-mode` with `{"mode":"AUTO"}` or `{"mode":"ASSIST"}`
- `POST /set-trading-mode` with `{"mode":"paper"}` or `{"mode":"live"}`
- `POST /set-symbols` with `{"symbols":["BTC/USD"]}`
- `POST /buy` with `{"symbol":"BTC/USD","qty":0.001}`
- `POST /sell` with `{"symbol":"BTC/USD","qty":0.001}`
- `POST /close-position` with `{"symbol":"BTC/USD"}`
- `POST /emergency-stop` with `{"reason":"manual"}`

## Risk Controls

The bot blocks orders when any of these conditions are active:

- emergency stop
- repeated API/runtime failure circuit breaker
- max daily loss lock
- losing-trade cooldown
- max open positions limit
- minimum order interval
- zero or negative order quantity

AUTO mode also refuses autonomous entries while paused or while `BOT_MODE=ASSIST`.

## Strategy

The strategy preserves the original rule:

- buy when latest close is above the supertrend and no position is open
- sell when latest close is below the supertrend and a position is open
- otherwise hold

The supertrend length is `7` and multiplier is `3`, matching the original script.

## Known Limitations

- No persistent database is used; state is reconciled from Alpaca after restart.
- Manual close and order endpoints depend on Alpaca account permissions and market
  availability.
- Live trading requires a separate explicit configuration change.
- Free-tier Render services may sleep, which can interrupt continuous monitoring.
